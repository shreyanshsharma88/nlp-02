## 4. Experimental design
1. Fine-tune both models with identical hyper-parameters, data and seed; select checkpoint by validation entity F1.
2. Repeat for seeds 13, 42, 1234 → mean ± std of test metrics (seed 42 run = "primary" run used for detailed analysis).
3. Test-set evaluation: 4 metrics + per-type P/R/F1 + macro F1 + seqeval report; validation metrics too.
4. Paired bootstrap (1,000 resamples over test sentences) on F1(cased) − F1(uncased): overall, PER, ORG (+LOC, MISC); McNemar on word-level correctness.
5. Case-perturbation: test set as (a) original (b) lowercase (c) UPPERCASE (d) Title Case, gold labels unchanged; F1 overall + per type; check uncased (a)==(b).
6. Slices on original test: entity-token shape (Title / ALL-CAPS / lower / mixed), sentence-initial vs mid-sentence, ALL-CAPS-headline vs normal sentences; recall per slice, PER/ORG broken out.
7. Case-ambiguous words (lowercase form seen as entity and as non-entity in train): accuracy per model.
8. Custom minimal pairs (16 sentences) side by side.
9. Error analysis: FN / FP / wrong-type / boundary per type, confused pairs, top mis-tagged tokens, disagreements (only-cased-right vs only-uncased-right, 10 annotated each), seen vs unseen entities, annotation-noise examples.

## 6. Metric definitions
- **Precision / Recall / F1 — ENTITY-level, micro-averaged** with `seqeval` (default conlleval-compatible mode):
  an entity counts as correct only if its type and its exact span match.
- **Accuracy — TOKEN-level** (= word-level, since only the first sub-token of each word is labelled):
  fraction of words whose predicted tag equals gold, ignoring -100 positions. Includes `O` so it is high (~98–99%).
- **Per-entity-type P/R/F1** for PER, ORG, LOC, MISC (seqeval), **macro F1** = unweighted mean of the 4 type F1s.
- Significance: paired bootstrap 95% CI on ΔF1; McNemar (continuity-corrected χ², 1 df) on word correctness.

## 12. Audit fixes (plan audited against brief)

| Issue found | Fix |
|---|---|
| Accuracy could be read as entity-level | Defined explicitly as token(word)-level, -100 ignored; labelled everywhere |
| Macro F1 not obviously defined | Defined as mean of 4 per-type F1s |
| fp16 differs CUDA vs MPS → unfair if models trained on different hardware | Both models trained in the same run on the same device; fp16 flag is device-driven, never per-model |
| MPS kernels are not bit-deterministic | 3 seeds + bootstrap CIs; claims only where CI excludes 0 |
| Label alignment risk (sub-tokens, specials, truncation) | Unit tests; count truncated words; eval on word level so every word is scored |
| Test leakage | Checkpoint picked on validation only; test touched only after training; case-ambiguous vocabulary and seen/unseen sets built from **train** only |
| Case-perturbed `upper()` can change token text length (ß→SS) — labels per word stay aligned since transform is per word | Test: transform keeps word count & labels; uncased (a) vs (b) differences reported and explained |
| Title-case via `str.title()` breaks `McDonald's` → `Mcdonald'S` | Custom title transform: first char upper, rest lower |
| Prediction word aggregation must match training | Predict uses first sub-token, same as training labels |
| Seqeval lenient vs strict | Report default (conlleval) as primary (comparable to literature); strict IOB2 F1 also stored |
| "Explain capitalization" weak if only F1 table | Added slices, ambiguous words, sentence-initial, headline caps, minimal pairs, tokenizer [UNK]/split stats |
| Notebook must not need GPU to re-run | `TRAIN=False` loads `results/`; custom predictions fall back to CSV if checkpoints absent |
